# NFC门店寻宝增长系统 - 项目总结构

## 1. 产品定位

**一句话定位**：面向线下餐饮门店的NFC+ H5寻宝闯关增长系统，通过游戏化任务体系帮助商家实现到店用户的社交传播裂变。

**目标验证**：到店用户愿不愿意通过H5完成任务，商家愿不愿意为这个结果付费。

**核心价值**：
- 给门店：低成本获客 + 真实内容生产 + 复购激励
- 给用户：免费福利 + 寻宝游戏体验 + 社交炫耀素材
- 给平台：商家服务费 + 数据资产 + 联盟导流

---

## 2. MVP核心闭环

```
用户到店 → 碰NFC桌贴/扫码 → 进入H5寻宝闯关页 → 完成三关任务
                                                      ↓
                                              商家审核任务
                                                      ↓
                                              用户领取奖励
                                                      ↓
                                              数据记录存档
```

**三关任务体系**：

| 关卡 | 触发动作 | 完成任务 | 奖励 |
|------|----------|----------|------|
| 第一关 | 碰NFC桌贴 + 加企微 | 添加商家企业微信好友 | 解锁电子寻宝地图 + 免费饮品券 |
| 第二关 | 门店打卡点拍照 + 大众点评打卡 | 拍照打卡 + 点评上传 | 解锁招牌荤菜券 |
| 第三关 | 抖音/小红书发布种草内容 | 发布带门店话题的种草笔记 | 解锁甜品券 + 当日霸王餐抽奖资格 |

---

## 3. MVP范围（本期做）

### 3.1 产品形态
- NFC桌贴物理入口（提供贴纸规格，不自研硬件）
- 二维码入口（与NFC并列，可选）
- H5用户端（微信内嵌，承载寻宝闯关流程）
- Web商家后台（任务配置、审核、优惠券管理）
- 平台管理后台（商家入驻、数据看板、结算）

### 3.2 核心功能
- **用户端**：NFC/扫码识别 → 闯关引导页 → 三关任务展示 → 领券页 → 核销记录
- **商家端**：门店配置 → NFC贴纸绑定 → 任务素材上传 → 审核任务 → 优惠券配置 → 核销管理
- **平台端**：商家入驻审核 → 门店关联 → 数据看板 → 基础结算
- **任务引擎**：任务触发规则 → 状态机流转 → 奖励发放
- **AI种草文案**：基于门店特色生成种草文案模板（仅文字，不做视频剪辑）
- **奖励与核销**：优惠券生成 → 领取 → 线下核销 → 状态回写
- **数据埋点**：关键节点埋点 → 简单看板展示

### 3.3 技术边界
- 微信内嵌H5（不申请小程序，不出微信生态）
- 商家后台：Web端即可（不做App）
- 核销方式：商家手动确认 + 券码验证
- 内容平台：仅抖音/小红书文字内容（不做自动视频剪辑）
- 异业联盟：本期仅支持本系统内多门店联动，不做跨平台联盟

---

## 4. 非MVP范围（本期不做）

| 类别 | 暂不做内容 | 原因 |
|------|-----------|------|
| 入口形态 | 独立App、完整小程序 | 降低用户门槛，先验证H5可行性 |
| 内容创作 | 自动视频剪辑、多平台API深度打通 | AI能力不成熟，先做文字模板 |
| 支付结算 | 银行托管分账、广告投放系统 | 初期人工对账足够 |
| 联盟扩展 | 全国异业联盟、跨品牌积分互通 | 先跑通单品牌/单区域模型 |
| 高级功能 | 智能推荐、用户LBS匹配、会员体系 | 等核心闭环验证后迭代 |

## 5. 八大模块拆解

### 模块A: 用户端H5寻宝闯关页

**模块职责**：承载用户在微信内的全部交互流程

**功能清单**：
- NFC碰一碰识别（读取预设scheme跳转H5）
- 扫码识别（QR码包含门店ID+场景参数）
- 寻宝地图页（SVG/Canvas绘制，电子地图解锁动画）
- 三关任务卡片（进度展示、任务说明、领奖入口）
- 第一关：NFC碰一碰 + 企微二维码 + 加微结果回调
- 第二关：打卡点拍照上传 + 大众点评链接跳转 + 点评截图上传
- 第三关：AI文案生成辅助 + 抖音/小红书跳转 + 内容链接回填
- 优惠券领取页（券码+使用说明）
- 霸王餐抽奖页（当日有效，次日开奖）
- 个人任务记录页（已完成/待领取/已失效）

**技术方案**：
- 前端框架：Vue3 + Vant组件库
- 唤起方式：URL Scheme（Android）/ Universal Link（iOS）或微信开放标签
- 图片上传：七牛云直传
- 地图绘制：SVG动画 + Lottie

**验收标准**：
- 微信内打开流畅（首屏 < 2s）
- NFC碰一碰成功唤起H5（Android 80%+/ iOS 60%+）
- 三关任务可独立完成，互不阻塞

---

### 模块B: 商家后台

**模块职责**：商家自主配置门店、任务、审核、运营

**功能清单**：
- 门店信息管理（名称、地址、营业时间、联系人）
- NFC贴纸管理（贴纸数量、绑定状态、挂失补发）
- 二维码生成与下载（支持批量）
- 打卡点配置（门店特色拍照点设定，最多5个）
- 任务素材上传（文案模板、图片、话题标签）
- 优惠券配置（饮品券/荤菜券/甜品券，发放数量、有效期、核销码规则）
- 任务审核（用户提交内容的人工审核 + 审核状态通知）
- 核销管理（券码验真、确认核销、核销记录导出）
- 数据概览（当日任务完成数、发放券数、核销数）

**技术方案**：
- 前端框架：React + Ant Design Pro
- 后端：Node.js + Express / Nest.js
- 数据库：PostgreSQL（商家主数据）+ Redis（缓存）
- 文件存储：七牛云

**验收标准**：
- 商家可在10分钟内完成新店配置上线
- 审核任务延迟不超过30分钟（需人工介入的场景）
- 核销操作步骤不超过3步

---

### 模块C: 平台管理后台

**模块职责**：平台方运营管理、商家资质审核、数据总览

**功能清单**：
- 商家入驻审核（营业执照、法人信息、风控初筛）
- 门店关联管理（门店与商家的绑定关系）
- 全局数据看板（DAU/MAU、任务完成量、优惠券核销率、GMV）
- 商家分成比例配置（平台:商家可调整）
- 结算管理（按周期生成账单，支持导出）
- 话题标签管理（#品牌名#、#门店名#等统一配置）
- 系统公告推送（推送给商家端App/Web）
- 权限管理（运营、客服、财务角色分离）

**技术方案**：
- 前端框架：React + Ant Design Pro
- 后端：Node.js + Nest.js
- 数据库：PostgreSQL + Redis
- BI看板：引用ECharts / DataV

**验收标准**：
- 商家入驻审核流程可在一小时内完成（材料齐全）
- 数据看板延迟不超过T+1（小时级更新）
- 支持按门店/按日期/按商家维度的数据导出

---

### 模块D: 任务引擎

**模块职责**：定义任务规则、驱动任务状态机、管理任务生命周期

**功能清单**：
- 任务模板配置（关卡、类型、触发条件、奖励、审核方式）
- 任务实例创建（用户进入时初始化三关状态）
- 状态机流转（待开始→进行中→待审核→已完成/已失败）
- 条件判定（NFC碰一碰事件、加微回调、打卡位置校验、内容链接校验）
- 奖励发放触发（审核通过后自动发放优惠券）
- 任务超时处理（24h未完成自动失效）
- 任务重置（商家可手动重置用户任务进度）

**技术方案**：
- 核心逻辑：状态机模式（XState或自研）
- 事件驱动：RabbitMQ / Kafka（任务事件流转）
- 缓存层：Redis（任务状态缓存，TTL 48h）

**验收标准**：
- 任务状态变更延迟 < 1s（同步场景）
- 同一用户同一门店同时只能有一个进行中的任务
- 奖励发放成功率 > 99.9%

---

### 模块E: AI种草文案模块

**模块职责**：基于门店特色自动生成种草文案，降低用户发布门槛

**功能清单**：
- 门店特色信息提取（菜系、招牌菜、环境风格）
- 文案模板库管理（运营可配置模板变量）
- 动态文案生成（填入门店名+招牌菜+话题标签）
- 文案风格选择（探店风/接地气/文艺风）
- 配套图片素材推荐（从商家上传素材中AI推荐）
- 生成记录日志（便于统计AI使用量）

**技术方案**：
- AI能力：接入通义千问 / GPT（文案生成）
- 图片推荐：接入阿里云视觉分析（场景识别）
- 缓存：生成过的文案结果缓存24h

**验收标准**：
- 单次文案生成 < 3s
- 生成文案可读性达标（运营抽检通过率 > 80%）
- 支持商家自定义禁用词过滤

---

### 模块F: 奖励与核销模块

**模块职责**：优惠券全生命周期管理，支持线下核销

**功能清单**：
- 优惠券模板配置（类型、面值、数量上限、有效期、使用条件）
- 优惠券生成（领取时创建实例，绑定用户+商家+订单）
- 券码体系（数字码/二维码，支持加密）
- 领取记录（用户ID、门店ID、券码、状态）
- 核销流程（商家扫码/输入券码→系统验证→确认核销→状态回写）
- 核销通知（用户收到核销成功通知）
- 优惠券退券（未使用状态下支持退券）
- 库存预警（剩余券数 < 10%时通知商家）

**技术方案**：
- 券码生成：UUID + HMAC签名防伪造
- 存储：PostgreSQL（主数据）+ Redis（高频查询）
- 通知：微信订阅消息 / 短信

**验收标准**：
- 券码验证 < 500ms（毫秒级响应）
- 同一券码无法重复核销（幂等性保障）
- 核销记录永久保存，支持溯源

---

### 模块G: 数据埋点与看板

**模块职责**：全链路数据采集，支撑运营决策和效果验证

**功能清单**：
- 埋点规范（事件命名、参数格式、上报时机）
- H5端埋点（页面PV/UV、NFC触发、任务每步完成、券领取/核销）
- 商家端埋点（登录、操作行为）
- 平台端埋点（登录、运营操作）
- 数据清洗（归因、去重、分渠道）
- 基础看板（实时数据大屏 + 历史趋势图）
- 核心指标：NFC触发率、任务完成率、券核销率、用户留存

**技术方案**：
- 埋点SDK：自研（mini-axios）或引入GrowingIO / 神策
- 数据仓库：MySQL（轻量级）/ ClickHouse（中等规模）
- 可视化：ECharts / DataV
- 定时任务：Node-cron /xxl-job（T+1报表）

**验收标准**：
- 埋点覆盖率 > 95%（核心事件无遗漏）
- 数据延迟 < 5min（实时看板）
- 支持按门店/渠道/日期维度下钻

---

### 模块H: 异业联盟模块

**模块职责**：本期仅支持本系统内多门店联动，为未来联盟生态打基础

**功能清单**：
- 联盟分组（同一品牌或合作商家分组）
- 跨店任务（用户完成A门店任务后，可跳转B门店继续）
- 联合优惠券（多门店通用券，支持商家间结算）
- 话题联动（#品牌联盟#话题，统一话题标签）

**技术方案**：
- 联盟配置表（商家分组、权重分配）
- 跨店跳转：URL Schema带联盟参数
- 结算逻辑：按核销门店归属统计，季度对账

**本期范围**：仅实现数据层面的联盟分组，不做实时分账

## 8. GitHub分支策略

### 分支模型：Gitflow轻量版

```
main (保护分支，仅release合并)
  ↑
release/v1.0 (预上线分支)
  ↑
develop (开发主分支)
  ├─ feature/{模块}-{功能名}  (功能分支)
  ├─ feature/user-h5-寻宝地图
  ├─ feature/merchant-console
  ├─ feature/task-engine
  ├─ bugfix/{模块}-{问题描述}
  └─ hotfix/{问题描述} (紧急修复)
```

### 分支规则
- `main`：永远保持可发布状态，代码审查必须通过
- `develop`：集成测试分支，每日合并一次
- `feature/*`：从develop拉取，完成后PR到develop
- `release/*`：上线前一周从develop拉取，冻结功能，专注bug修复
- `hotfix/*`：从main拉取，修复后同时合并到main和develop

### Commit规范
```
{type}({scope}): {subject}
type: feat | fix | docs | style | refactor | test | chore
scope: user-h5 | merchant | platform | engine | ai | data | ci
examples:
  feat(user-h5): 添加寻宝地图动画
  fix(task-engine): 修复并发状态下任务状态错乱
  docs(platform): 更新商家入驻流程文档
```

### PR规范
- 标题：`[模块] 功能描述`
- 内容：关联的issue、测试截图、影响范围说明
- 至少1人review通过方可合并

## 9. 项目验收标准

### 9.1 功能验收

| 模块 | 验收条件 | 验证方式 |
|------|----------|----------|
| H5入口 | NFC碰一碰唤起成功率 Android≥80% | 10台真机测试 |
| H5入口 | 扫码唤起成功率 ≥95% | 扫码测试100次 |
| 用户任务 | 三关任务完整流程可独立完成 | 手动遍历测试 |
| 商家后台 | 新门店配置上线 ≤10分钟 | 运营人员实测 |
| 商家审核 | 审核延迟 ≤30分钟（90分位） | 日志统计 |
| 核销 | 券码验证 <500ms | 性能测试 |
| AI文案 | 生成成功率 ≥95% | 自动化调用1000次 |
| 数据看板 | 核心指标与日志误差 <1% | 对账验证 |

### 9.2 非功能验收
